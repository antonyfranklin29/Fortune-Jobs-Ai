# Guest résumé matching — October 11, 2026

The Home and Find Jobs upload buttons now open resume-search.html without signing in. Text-based PDF and DOCX files are read locally, with the existing 5 MB, 30-page PDF and 60,000-character extraction limits. The document is not uploaded to résumé storage, and guest searches do not load, create or update an account profile or search history.

Automatic detection uses the supported title/skill catalog, explicit experience statements or dated work-history intervals, and header/home-location patterns. The most recently dated detected role is preferred when there is no explicit target/header title. Overlapping employment intervals are counted once; date-derived experience is labeled approximate. Education dates, future employment intervals and employer addresses under work history do not establish home location or experience. Missing or uncertain role/location requires an editable summary rather than a guessed search. This is heuristic detection, not a guarantee of parsing every résumé layout or language.

When role and home location are clear, an automatic Live Search opens the dedicated results page. For Edison, NJ, the default searches New Jersey; the visitor can switch to Edison only. Original listing state/country and title evidence remain mandatory. State abbreviation aliases are normalized; unknown geographic evidence is excluded. Experience and skills personalize ranking after source-backed accuracy filters. The results summary allows changing title, experience, city/region, skills and Quick Match/Live Search.

Only a reduced profile (title, detected role choices, skills, years of experience and city/region/country) is kept in sessionStorage with a two-hour expiry. No full text, file, name, email, street address or résumé filename is persisted there. Each résumé has an opaque matching ID, so an older results link cannot silently use a different newly uploaded résumé. Guests can clear details from the upload editor or results page. Live Search receives the job query and search filters, not résumé content or profile identity.

Verification: 47 automated tests passed, including a real DOCX file-input event through extraction, temporary storage and results navigation without account APIs; actual PDF/DOCX extraction, malformed files, experience overlaps, location safety, state filtering, profile binding/expiry, and existing search regressions. Six existing production Quick Match accuracy cases passed unchanged. Local anonymous browser tests using synthetic fixtures and the production backend returned six New Jersey Data Analyst jobs from PDF and seven from DOCX, with evidenced profile-skill reasons. Editing the search area to Edison, clearing details and prompting for a missing home location were also checked in the browser.

Native automated file selection is unavailable because Chrome's extension file-URL access is disabled. Browser fixtures were loaded through an isolated local test page using the same extraction code, and the actual DOCX input-change handler was covered independently. The development fixture controls are not shipped. No real person's résumé or account was overwritten.

The existing ten-result limit and subscription prompt remain; paid checkout is still a separate launch item. Scanned PDFs need OCR/conversion first. This feature does not complete the full security or concurrent-live-search audit.
