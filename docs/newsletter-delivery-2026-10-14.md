## Components
- `newsletter/email.mjs`: Option C HTML + plain text; fixed sender/reply address info@fortunejobsai.com, hosted logo, postal footer, preferences and unsubscribe. No tracking pixel or open/click analytics.
- `email-preferences.html` / `newsletter-preferences.js`: unchecked by default; authenticated optional subscription, weekly cadence; explicit unavailable state if backend is absent. Never claims success after a failed request.
- `supabase/functions/email-preferences/index.ts`: JWT validated against Auth; user identity comes only from that verified response. Server timestamps, consent version weekly-v1. GET never changes preferences. Signed unsubscribe GET displays confirmation; POST removes subscription without login, including RFC 8058 one-click POST.
- `migrations/20261014_newsletter.sql`: owner SELECT only; no anonymous/client direct writes; service-only RPC claim; auth-user deletion cascades preferences and delivery records. Daily 80-reservation ceiling, at most one send per seven days per user, unique recipient/campaign claim. Unknown/reserved deliveries block automatic retries, even on a later date.
- `scripts/newsletter-worker.mjs`: manual dry-run by default. Requires verified email, explicit opt-in, saved role and geographic filters. Reads latest 1000 jobs posted within seven days, rejects stale/future/expired/irrelevant listings with existing matching rules, max five jobs. A sparse corpus skips that issue. The 1000-row scan is a known coverage limitation; no claim of global or exhaustive matching.
