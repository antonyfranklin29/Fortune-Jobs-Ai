# State, city and role job pages

Run `node --test tests/job-seo.mjs` and `node scripts/build-job-seo.mjs` from the repository root. The builder reads the public catalogue and updates `jobs/` and `sitemap.xml`. Review the generated diff before release. All 26 catalogue roles get city pages in 19 cities. City pages with fewer than five distinct open listings stay out of the sitemap and use `noindex`. State pages are generated only at 40 distinct open listings and are removed when they fall below that threshold. Counts use public, open U.S. rows with a usable HTTPS application URL, deduplicated by application URL within the area and role. The page shows up to 20 listings.

Single-job pages add Google for Jobs markup after verifying that a direct employer listing is open and has a description, a physical U.S. location, a closing date and an HTTPS application link. City pages show listing summaries with source credit. Third-party jobs and email-only applications are outside the first markup release.

Regenerate when a direct posting opens or closes and on a regular cadence for city snapshots. The job page rechecks availability on every visit and omits structured data for closed or expired jobs. Regeneration removes obsolete single-job pages and sitemap entries. The daily workflow uses the existing anonymous catalogue configuration and opens or updates the generated snapshot PR. Repository Actions settings must allow GitHub Actions to create pull requests. The workflow never writes to main. Indexing API setup is outside this workflow. Check the first eligible public posting with Google's Rich Results Test before requesting indexing. [Google's job posting documentation](https://developers.google.com/search/docs/appearance/structured-data/job-posting)
